# Design gate and acceptance criteria

## Gate 1 — Moodboard

Select one direction only if it demonstrates:

- a single dominant focal idea;
- premium typography before texture;
- black/cream/cherry without generic goth or diner nostalgia;
- punk materiality used with intent;
- a believable home for real software, research, game, and book evidence;
- enough restraint that résumé and contact remain obvious.

## Gate 2 — Homepage stills

Approve a full desktop composition and a separately composed 320 px mobile
version before frontend rebuilding.

The stills must answer the ten-second test and show:

- hero, identity, résumé, and contact;
- four flagship encounters with one action each;
- a quiet archive rather than a card wall;
- a human/about beat;
- a closing poster;
- realistic content density using verified copy;
- real or explicitly marked provisional evidence.

## Gate 3 — Representative case studies

Prototype three static case studies:

- software: HEARTLINE;
- research: CancerShift;
- writing: Flooded.

Shared skeleton:

1. one-sentence orientation;
2. role, status, timeframe only when verified;
3. dominant evidence object;
4. the problem or question;
5. decisions/process;
6. strongest proof;
7. limits and publication boundary;
8. repository/live link when one exists;
9. one intentional next-project transition.

The evidence language changes by discipline:

- software shows a task, interface state, architecture, and repository;
- research separates methods, findings, and limitations visually;
- writing shows material process and only approved language.

## Gate 4 — Build readiness

Frontend implementation may begin when:

- one moodboard is explicitly selected;
- desktop and mobile stills are approved;
- the three case-study prototypes feel related without being templates;
- every required hero asset is approved or has a named capture owner;
- the copy sheet contains no unresolved invented language;
- 3D and motion have complete fallbacks and measurable budgets.
